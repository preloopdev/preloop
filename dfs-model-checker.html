aksh DFS Model Checker

Systematic state-space verification of the GitHub Actions concurrency state machine

● 338 unique states ● 6 depth bound ● 3 runs × 2 groups ● 2 queue modes ● 4 invariants ● 0 divergences

1. Dual-State Architecture

Two independent implementations run in parallel at every step: a clean-room model and the live production code. Every operation is applied to both, then cross-checked for equivalence.

Key insight: The model is pure logic (~250 lines, zero production imports). The prod wrapper calls real InnerState functions verbatim. If they ever disagree on running/pending holders, the test panics with the full op sequence.

2. Independent Reference Model

The model tracks three data structures to mirror GitHub's concurrency semantics exactly:

groups

BTreeMap<(repo,group), ModelGroup>

Each group has exactly one running slot plus a pending FIFO deque. → at most one running holder per group

holder_state

BTreeMap<HolderToken, HolderState>

Every holder token maps to Running / Pending / Cancelled / Terminal. → single source of truth for lifecycle

holder_keys

BTreeMap<HolderToken, BTreeSet<key>>

Reverse map: for every holder, what groups is it in? Multi-key holders (JobSets) appear in multiple groups. → prevents ghost keys on cleanup

// The four invariants checked at every node:

// INV-1: At most one running holder per group
fn check_inv1(&self) -> Result<(), String> { ... }

// INV-2: Running and pending sets are disjoint
fn check_inv2(&self) -> Result<(), String> { ... }

// INV-7: Every running/pending holder has exact reverse key
fn check_inv7(&self) -> Result<(), String> { ... }

// INV-12: Empty groups are immediately removed
fn check_inv12(&self) -> Result<(), String> { ... }

6. What Catches a Real Bug

Here's what happens when production diverges from the model — a simplified version of the self-deadlock bug found in the original promotion state machine:

    end

    subgraph ProdState["❌ Production (buggy)"]

        PH["holder_keys: {run0 → {grp-1}}"]
    end

    subgraph Check["Snapshot Equivalence"]
        C1["running: run0 ≡ run0 ✓"]
        C2["pending: [] ≠ [run0] ✗"]
    end

    MR --> C1
    PR --> C1
    MR --> C2
    PR --> C2

    C2 -->|"MISMATCH"| PANIC["💥 panic with path dump
→ exact op sequence to reproduce"]

The bug: a promotion moves run0 to "pending" while it still holds the running slot. The model's INV-2 (disjoint running/pending) catches this immediately. The production version had the exact same flaw — a job was moved to concurrency_blocked without releasing its holder_keys.

7. State-Space Pruning

Without deduplication, the DFS explodes combinatorially (~50K branches). The visited set compresses multiple execution paths into the same equivalence class by hashing the post-op groups + holder_state.

8. Generation Loop (Pseudocode)

fn dfs(depth, model, prod, path, visited): // Invariants must hold at every node assert model.check_all_invariants().is_ok() assert check_production_invariants(&prod.inner).is_ok() assert snapshots_equivalent(model, prod) if depth >= 6: return // Enumerate EVERY valid next op for run in [0, 1, 2]: if run not already holding: for group in ["grp-1", "grp-2"]: for queue in [Single, Max]: for cancel in [false, true]: ops.push(Submit { run, group, queue, cancel }) for group with a running holder: ops.push(Release { group.running }) for every Running or Pending holder: ops.push(Cancel { holder.run }) // Branch, check, prune duplicates for op in ops: next_model = model.clone() next_prod = prod.clone_concurrency() execute_op(&mut next_model, &mut next_prod, &op) if visited.insert(state_key(next_model)): path.push(op) dfs(depth + 1, next_model, next_prod, path, visited) path.pop()
