# aksh Improvement Plans — Compatibility-first, then Refactor

Generated by the `improve` skill. This directory now holds **two phases**:

- **Phase A — Compatibility (Step 1): fix divergences from the official `actions/runner`
  BEFORE refactoring.** Refactoring locks in behavior; fixing wire/semantic divergences
  first means the refactor preserves *correct* behavior, not current-but-wrong behavior.
- **Phase B — Refactor (Step 2): reduce bloat, split god-files, dedupe, improve
  hygiene — WITHOUT changing official-runner-visible behavior.**

**Authority for every compatibility claim**: the vendored official `actions/runner`
C# source at `/Users/bnjoroge/mitm-proxy/experiments/mitm/.cache/runner.server/src`
(`Runner.Worker`, `Runner.Listener`, `Runner.Common`, `Sdk`; pin v2.335.1) plus real
GitHub wire captures at `.runner-watch/golden/v2.335.1/`. ChristopherHX's `Runner.Server`
is a non-authoritative hint only (per `AGENTS.md`); GitHub's published schema
(`Sdk/DTPipelines/workflow-v1.0.json`) IS authoritative for control-plane semantics.

## Dependency notes

- **012 is the refactor keystone** — moving tests out of production files shrinks every
  god-file (~6,478 lines out of lib.rs alone) and makes 015/016/017 tractable. Do it
  first in Phase B.
- **014(A)** (PipelineContextData null fix) and **013** (matrix unify) carry correctness
  weight — schedule them early even though they live in Phase B.
- **015/016/017** depend on 012 (smaller files) and 014 (shared helpers to import).
- **006** (concurrency differential) depends on **007** (the one-pending model must be
  settled before the property model asserts it).
- **018 part B** (error mapping) is cleaner after **015** extracts `errors.rs`.

## Direction notes (options for the maintainer, not ranked against bugs)

- **`queue: max` is a fork in the road** (Plan 007). It's a well-built aksh feature that
  GitHub's schema doesn't have. Decide: strict portability (remove/reject it) vs.
  documented non-standard extension (keep + validate + document). This is a product call,
  not a bug — the plan defaults to strict but implements either.
- **State-boundary refactor (follow-up to 015)**: after lib.rs is split, `InnerState`'s
  ~70 fields could become per-subsystem sub-state with accessors. High value, but it's a
  behavior-sensitive refactor deserving its own plan once modules exist — deliberately
  NOT bundled into the pure-move plan.
- **`JobContext`/`StepContext` access model (follow-up to 016)**: replacing the
  unrestricted `&mut JobContext` with an explicit `JobState` API would clarify
  step-vs-job mutation scope. Its own plan after the worker modules exist.

## Findings considered and rejected (do not re-audit)

Carried forward from the prior audit + this pass (all re-confirmed as non-issues):

- **TaskResult PascalCase** — VSS formatter serializes camelCase; golden captures are lowercase; aksh matches.
- **`messageType` DTO default** — server sets it on every broker acquire; default is irrelevant.
- **Artifact/cache Twirp schema (`created_at`/`expires_at`/`version`/`CacheMetadata`)** — present or tolerantly-ignored request fields; response shapes match the toolkit proto.
- **Session `ephemeral`/`status`/`provisioningState`** — legitimate `TaskAgentReference` members.
- **`go`/`plugin` action types** — `go` never an official `runs.using`; `plugin` is runner-internal.
- **AzDO-path-only issues** (agent fields, unbounded 409 retry, no dedup) — legacy path deferred by design (`AGENTS.md`: broker path only).
- **`lockedUntil` absent from `AgentJobRequestMessage` DTO** — nullable upstream; deserializes fine (the *renewal* handling in Plan 003 is the real issue, not the field).
- **First-renew-blocking before worker start** — official blocks job start on first renew; aksh starts concurrently. Defensible tradeoff; revisit only if Plan 003 surfaces lease races.
- **Concurrency expression allowlist** (workflow scope excludes needs/strategy/matrix) — verified CLEAN in `concurrency.rs:129-177`; preserve it through Plan 014(B).
- **PR ref/SHA mapping, cron conversion, matrix max-parallel/fail-fast gating, condition truth tables, OIDC RS256/claim shape** — all verified CLEAN against the official source in this pass.
- **Webhook default-branch SHA** — adapters leave SHA unset but `github.rs` resolves it before submission; CLEAN end to end.

## How to work these

Every plan is self-contained for a zero-context executor: drift check, current-state
excerpts, exact commands, scoped steps with verification, done criteria, STOP
conditions. Run `cargo fmt`, `cargo clippy --workspace --all-targets -- -D warnings`,
and `cargo test --workspace --quiet` (the `justfile` `test-ci` target) as the gate.
For any change to runner-facing routes/payloads, validate against the **official
runner** (dogfood / conformance), not only unit tests (`AGENTS.md`).
