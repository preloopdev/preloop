## Findings considered and rejected (do not re-audit)

- **TaskResult casing (broker completejob)** — golden captures show the official runner's real
  run-service wire is lowercase (`"conclusion": "failed"`); aksh matches. The PascalCase in
  `TaskResult.cs` is serialized camelCase by the VSS formatter.
- **`messageType` always None in job message** — the server sets it on every broker acquire
  response; the DTO default is irrelevant.
- **Artifact/cache Twirp schema gaps (3 claims)** — vetted false: `created_at` IS in the
  ListArtifacts response (`lib.rs:3525`); `expires_at`/`version`/`CacheMetadata` are *request*
  fields serde tolerantly ignores; response shapes match the toolkit proto.
- **Session body "extra" agent fields (`ephemeral`,`status`,`provisioningState`)** — these are
  legitimate `TaskAgentReference` members, not extras.
- **`go`/`plugin` action types unsupported** — `go` was never an official `runs.using`;
  `plugin` is runner-internal, unpublishable on the marketplace.
- **AzDO-path session findings (agent fields, unbounded 409 retry, no dedup)** — legacy path,
  deferred by design (`AGENTS.md`: broker path only).
- **`lockedUntil` absent from `AgentJobRequestMessage` DTO** — nullable upstream; absence
  deserializes fine. Not worth a plan on its own.
- **First-renew-blocking before worker start** — official blocks job start on first renew;
  aksh starts concurrently. Behavioral nuance with a defensible tradeoff; revisit only if 003
  surfaces lease races.
- **/twirp 401 for the Rust-runner smoke (docs/fidelity-gap.md note)** — likely stale: twirp
  routes were since moved outside `require_bearer` precisely to accept job tokens. Folded into
  plan 005 verification.
