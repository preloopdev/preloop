# Memory-Hardening Repro Progress

Contract: `.omp-repro.md` (authenticated-runner memory exhaustion, Medium).

Approach mirrors the already-shipped live-log cap (`live_logs.rs::LiveLogBuffer`):
every sink an authenticated runner can grow across many `200 OK` requests is
bounded by a documented constant in `memory_caps.rs`. Repro tests drive each
sink the way a malicious runner would (runner-listen or job runtime tokens,
repeated accepted requests), capturing **before** evidence that the sink grew
past its budget, then **after** evidence that the cap/413/eviction holds.
`repro_f*` tests are `repro_fN_*` in `lib_tests.rs`; the retention helpers have
direct unit tests in `memory_caps.rs::tests`.

## Cap constants (`memory_caps.rs`)

| Sink | Constant | Value |
| ---- | -------- | ----- |
| F1 per-log retained bytes | `MAX_LOG_BYTES_PER_KEY` | 16 MiB |
| F1 per-plan retained bytes | `MAX_LOG_BYTES_PER_PLAN` | 64 MiB |
| F1 per-plan log entries | `MAX_LOGS_PER_PLAN` | 512 |
| F2 per-timeline records | `MAX_TIMELINE_RECORDS` | 1024 |
| F2 global timeline keys | `MAX_TIMELINE_KEYS` | 4096 |
| F3 per-run events (ring) | `MAX_TIMELINE_EVENTS` | 2048 |
| F3 global event run-keys | `MAX_TIMELINE_EVENT_KEYS` | 4096 |
| F5 per-block | `MAX_BLOCK_BYTES` | 4 MiB |
| F5 blocklist id count | `MAX_BLOCKLIST_BLOCKS` | 10 000 |
| F5 assembled blob | `MAX_ASSEMBLED_BYTES` | 512 MiB |
| F6 GET page cap | `MAX_TOP_RECORDS` | 500 |
| F7 pending uploads per job | `MAX_PENDING_PER_JOB` | 32 |
| F7 cache download tokens | `MAX_CACHE_DL_TOKENS` | 1024 |
| F7 artifacts per run | `MAX_ARTIFACTS_PER_RUN` | 500 |
| F7 global artifact registry | `MAX_ARTIFACT_REGISTRY_ENTRIES` | 10 000 |
| F7 pending/TTL | `PENDING_UPLOAD_TTL` | 1 h |

## Before/after evidence

All before runs are the same repro tests against the pre-fix tree (constants
module present, no enforcement). After runs are the same tests with the
enforcement in place.

### F1 — unbounded `logs` (`append_log`)

| Test | Before | After |
| ---- | ------ | ----- |
| `repro_f1_log_append_is_bounded_per_key` — 320 × 64 KiB into one log key | 20 971 520 bytes retained (> 16 MiB cap) — FAILED | ≤ 16 MiB, appends still 202 — ok |
| `repro_f1_log_flood_across_log_ids_is_bounded_per_plan` — 9 logs × 8 MiB | 75 497 472 bytes retained (> 64 MiB cap) — FAILED | ≤ 64 MiB, oldest log (`plan-1/1`) evicted, newest kept — ok |

Fix: `append_log` truncates the oldest bytes of the per-key buffer past
`MAX_LOG_BYTES_PER_KEY` (durable chunk store still receives every append);
`trim_plan_logs` evicts the oldest log of the plan past the byte and entry
budgets; `create_log` calls it too so empty-log floods stay bounded.

### F2 — unbounded `timeline_records`

| Test | Before | After |
| ---- | ------ | ----- |
| `repro_f2_timeline_records_are_capped_per_timeline` — 2000-record PATCH | 2000 records stored (> 1024 cap) — FAILED | ≤ 1024 — ok |

Fix: `patch_timeline_records` calls `trim_timeline_after_patch`, which evicts
the oldest-keyed records past `MAX_TIMELINE_RECORDS` and evicts whole
timelines (records + `timeline_change_ids` together) past
`MAX_TIMELINE_KEYS`.

### F3 — unbounded `timeline_events`

| Test | Before | After |
| ---- | ------ | ----- |
| `repro_f3_timeline_events_are_ring_buffered_per_run` — 25 × 100 status PATCHes | 2500 events (> 2048 ring cap) — FAILED | ≤ 2048 — ok |

Fix: `trim_timeline_events` drains the oldest events past
`MAX_TIMELINE_EVENTS` and bounds the number of distinct run buckets past
`MAX_TIMELINE_EVENT_KEYS` (fabricated plan ids otherwise mint unbounded
buckets).

### F5 — unbounded blob block assembly

| Test | Before | After |
| ---- | ------ | ----- |
| `repro_f5_blob_block_assembly_rejects_oversized_block` — 5 MiB block PUT | `201` (staged) — FAILED | `413` — ok |
| `repro_f5_blob_blocklist_count_and_total_budgets_are_enforced` — blocklist with 10 001 ids | `500` (missing-block read error, no count guard) — FAILED | `413` — ok |
| same test, total budget — 129 × 4 MiB blocks staged on disk then committed | `201` + 516 MiB assembly — FAILED | `413` up front (stat pre-check, no block read) — ok |
| `repro_f5_blob_block_assembly_still_produces_correct_blob` — 2 × 1 MiB blocks | `201` / GET returns concatenation, blocks dir removed — ok | unchanged — ok (protocol fidelity) |

Fix: `blob_put` rejects a single block > `MAX_BLOCK_BYTES` with 413, rejects a
blocklist > `MAX_BLOCKLIST_BLOCKS` ids with 413, stat-pre-checks the total
referenced bytes against `MAX_ASSEMBLED_BYTES` (413 before reading anything),
and `assemble_streaming` copies block files into the destination with a
running copy-total guard (partial destination removed on overflow) — the
assembled blob is never materialized in memory.

### F6 — unbounded timeline GET

| Test | Before | After |
| ---- | ------ | ----- |
| `repro_f6_timeline_get_is_paginated_and_capped` — plain GET after 2000-record seed | 2000 records returned in one response — FAILED | ≤ 500 — ok |
| `?skip=500&top=500` | (no pagination support) | exactly 500 — ok |
| `?top=9999` | (no pagination support) | clamped to 500 — ok |

Fix: `get_timeline_records` (and the `_plan` + GHES `_org` wrappers) accept a
`Query<TimelineQuery { top, skip }>`; `top` defaults to and is clamped at
`MAX_TOP_RECORDS`.

### F7 — unbounded pending maps / download tokens

| Test | Before | After |
| ---- | ------ | ----- |
| `repro_f7_artifact_v2_pending_uploads_are_capped_per_job` — 33 CreateArtifact on one job | 33rd → `200 ok:true` — FAILED | 33rd → rejected (409 conflict), pending ≤ 32 — ok |
| `repro_f7_cache_v2_pending_uploads_are_capped_per_job` — 33 CreateCacheEntry on one job | 33rd → `ok:true` — FAILED | 33rd → `ok:false` (non-fatal miss shape), pending ≤ 32 — ok |
| `repro_f7_cache_download_tokens_are_bounded` — 1032 GetCacheEntryDownloadURL hits | 1033 tokens (> 1024 cap) — FAILED | ≤ 1024, oldest evicted — ok |

Fix: the job is derived from the **signed runtime token scope**
(`Actions.Results:{plan}:{job}` via `job_backend_id_from_bearer`), never the
request body (spoofable). `twirp_artifact_v2_create` gained a `HeaderMap`
extractor and rejects a job past `MAX_PENDING_PER_JOB`; the cache create
refuses the same way with `ok:false`. Pending entries carry `job_backend_id`
and `created_unix` (`#[serde(default)]` so old persisted metas restore; `0`
timestamps are left alone by the sweeper). `twirp_cache_v2_get_dl_url` mints
into a FIFO-order map and `trim_cache_dl_tokens` evicts the oldest past
`MAX_CACHE_DL_TOKENS`. `twirp_artifact_v2_finalize` calls
`trim_artifact_registry` (500 per run / 10 000 global; verified by the
`memory_caps` unit tests — a 500/10 000-run HTTP repro would be impractically
slow). `reap_once` now runs `sweep_pending_uploads` every tick, dropping
pending uploads and download tokens older than `PENDING_UPLOAD_TTL`
(restored entries with `created_unix == 0` are never swept).
