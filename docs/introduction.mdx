title: Introduction
description: What Preloop runs, and whether you need the self-hosted control plane or the standalone runner.
---

Preloop runs GitHub Actions workflows on hardware-isolated microVMs. Your `.github/workflows` files stay unchanged. You choose where the jobs run: on your own machine, on servers you operate, or on hosts that register with GitHub.

Preloop ships as two products. You can use either one on its own.

![A failed step, a fix in another pane, and a re-run, all local with no push required](/demo/demo.gif)

<CardGroup cols={2}>
  <Card title="Control plane" icon="server" href="/control-plane/quickstart">
    Run unmodified workflows locally or on your own infrastructure. `preloop run` executes a workflow against your working tree, including uncommitted files. `preloop serve` runs the engine, which can start runs from GitHub pushes and pull requests through a GitHub App, and can pause a failed job so you can debug it.
  </Card>
  <Card title="Runner" icon="terminal" href="/runner/overview">
    A standalone, drop-in replacement for `actions/runner`. It registers with GitHub or a Preloop server, polls for jobs, and runs them on the host where it is installed. It needs no control plane, microVMs, or background services.
  </Card>
</CardGroup>
