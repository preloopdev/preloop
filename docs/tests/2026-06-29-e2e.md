## Follow-up review/fix pass — AgentRequest + plan correlation

This pass reviewed the partial matrix result above and found two concrete runner
protocol bugs:

1. **Missing `GET /_apis/v1/AgentRequest/:pool_id/:request_id`**.
   The official listener calls this when another job arrives while the previous
   worker dispatch is still unwinding. Returning `405 MethodNotAllowed` makes
   the listener cancel the worker. aksh now stores each request state and returns
   a `TaskAgentJobRequest`-shaped JSON document with `requestId`, `poolId`,
   `jobId`, `jobName`, `planId`, `planType`, `lockedUntil`, and `result`.
2. **Plan/timeline/job callback correlation**.
   `AgentJobRequestMessage.plan.planId` is the runner's orchestration plan UUID,
   not the aksh `RunId`. Timeline/log/FinishJob callbacks therefore could not
   safely parse `:plan_id` as `RunId`. aksh now indexes each request by
   `planId`, `timelineId`, and runner `jobId`, and uses that index to map
   callbacks back to the logical aksh `(run_id, job_id)`.

Additional fixes in the same pass:

- Added `POST /_apis/v1/AgentRequest/:pool_id/:request_id` as a best-effort
  request acknowledgement (`204 No Content`).
- The message queue now withholds additional job messages from the same runner
  session while that session owns an unfinished request, but still delivers
  cancellation messages before that busy-session gate.
- `FinishJob` now delegates through the same completion path as
  `AgentRequest` completion, so outputs, run summarization, dependency
  promotion, matrix `fail-fast`, and event emission stay consistent.
- `TaskResult::Cancelled` now serializes as the runner spelling `"canceled"`
  while still accepting the old `"cancelled"` spelling on input.
