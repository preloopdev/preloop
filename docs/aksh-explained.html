Runner Protocol Flow

Vertical lifecycle timeline mapping every HTTP request the official runner binary performs when executing against the control plane.

Key Stages

1. Registration: exchanges listener token and registers agent RSA public key.

2. Wait: long-poll endpoint returns job or 202 timeout.

3. Acquire: acquires job steps, env, and secrets.

4. Execution: streams logs and timelines.

5. Completion: reports status, outputs, and tears down session.

Workflow Engine

How a submitted YAML workflow goes through the parser, trigger matching, matrix expansion, and the dependency-gated Needs DAG scheduler.

01
Parallel Submission (api/v1/runs)
Two separate POST requests hit aksh-runner-server.
workflow-a.yml 
jobs:
  build:
    runs-on: self-hosted
  test:
    needs: build
    runs-on: self-hosted
workflow-b.yml 
jobs:
  lint:
    runs-on: self-hosted
02
Parsing, Trigger Matching & GHA Expressions
aksh-gha-parser parses both documents. Trigger::matches_with_context() validates branches. Matrix expansion is evaluated. Since no conditions fail, the engine generates three job specifications:
  • Workflow-A: build (Ready for scheduling)
  • Workflow-A: test (Held back — depends on build)
  • Workflow-B: lint (Ready for scheduling)
03
Needs DAG Gating & Queue Placement
The scheduler in aksh-runner-server inspects the job relationships and registers them in the state map.
1. Queue VecDeque (Runnable) [ A.build, B.lint ]
2. Held Gated Map (Pending) { A.test: [needs: A.build] }
04
Concurrent Message Dispatch (Long-Poll)
Two separate runner listeners (Runner 1 and Runner 2) are polling for jobs.
Runner 1 (session s1)
Polls messages on session s1. aksh pops A.build, generates TaskAgentMessage, encrypts, and dispatches it.
Runner 2 (session s2)
Polls messages on session s2. aksh pops B.lint, generates TaskAgentMessage, encrypts, and dispatches it.
05
Parallel Execution & Timeline Streaming
Both runners execute their steps concurrently, streaming progress back to aksh:
  • Runner 1 calls PATCH /Timeline/A_build with step logs.
  • Runner 2 calls PATCH /Timeline/B_lint with step logs.
  • aksh broadcast engine projects these updates into the native NDJSON feed in real-time.
06
DAG Evaluation & Downstream Unlock
Execution continues until completion:
  • Runner 2 finishes B.lint: calls FinishJob/B. aksh updates Workflow-B to Success. Runner 2 returns to idle.
  • Runner 1 finishes A.build: calls FinishJob/A. aksh saves A.build's outputs. The scheduler evaluates dependencies: A.build is complete, so A.test is unlocked!
  • A.test is pushed into the VecDeque queue.
  • Runner 2 (now idle) polls GET /messages?sessionId=s2, picks up A.test, and begins execution.

Walkthrough Details

How aksh coordinates two simultaneous workflow runs using parallel queueing.

1. State Registry

Both runs write to the same thread-safe SharedState (inside `InnerState` maps). Mutex locks protect the queue, active sessions, and timeline logs.

2. Port & Host Separation

The dispatcher knows where to send each job because the session_id maps to the runner's specific registration. Runner 1 (s1) and Runner 2 (s2) remain isolated.

3. Live NDJSON Projections

The REST API's /events.ndjson stream merges events from both runs. Observers see interleaved updates (e.g. A.build step started, B.lint step completed) indexed by `run_id`.

Crate Architecture

How the codebase is divided into modular, independent Rust crates.

SRV

aksh-runner-server

HTTP server written in Axum. Handles AzDO compatible endpoints, OAuth token generation, long-polling queues, broker endpoints, results Twirp services, and OIDC tokens.

PAR

aksh-gha-parser

Typed GHA workflow representation. Parses GHA YAML workflows, expands job matrices, handles branch/tag/path/trigger matching rules, and designs the Needs dependency graph.

EXP

aksh-gha-expressions

GHA Pratt parser and evaluator. Resolves expressions like ${ matrix.os == 'ubuntu-latest' && success() } against runtime context maps.

PRT

aksh-gha-protocol

Domain and wire data transfer models (DTOs) for the runner protocol. Handles serialization, encrypted envelope structs, and timeline record definitions.

MEM

aksh-cache / aksh-artifacts

In-memory Cache and Artifact storage providers (v1 format). Used to support artifact exchanges and timeline uploads in local dev scenarios.

CON

aksh-conformance

Verification harness. Integrates with the `runner-watch` tool to run golden capture replays, compare HTTP statuses, and verify control-plane behavior.
