## CRITICAL

### PEXP-01 · hashFiles produces wrong cache keys — **FIXED** (`1868e57`)
`crates/aksh-gha-expressions/src/lib.rs:472–490`

Official runner (`hashFiles.ts:29-35`) concatenates **raw binary digests** then SHA-256s them.
aksh formatted each digest as a hex string, concatenated those strings, and hashed the UTF-8 bytes.
Different algorithm → different keys on every call.

**Fix applied:** `combined.extend_from_slice(&digest[..])` using a `Vec<u8>` buffer.
Unit test `hashfiles_binary_digest_matches_official_algorithm` added.

#### Discovered during E2E: PJOB-01 · Step env/script pre-resolved without workspace — **FIXED** (`1868e57`)
`crates/aksh-gha-parser/src/job_builder.rs`

`build_task_step` was calling `resolve_map` / `resolve_string` on step `env` and `run` scripts at
job-build time. Since no workspace exists at build time, `hashFiles()` in step env always evaluated
to `""` before the runner ever saw the job. More broadly, any runtime expression (`steps.*.outputs`,
`github.action`, etc.) was silently zeroed at build time.

**Fix applied:** env and run scripts are now passed as raw template strings; the runner evaluates
them at step-execution time with full context (workspace, steps outputs, etc.) via the existing
`evaluate_template()` path. `with` inputs are still pre-resolved since action handlers need resolved
values to locate the action.

#### Discovered during E2E: PPAR-01 · Step `if:` conditions silently dropped — **FIXED** (`1868e57`)
`crates/aksh-gha-parser/src/lib.rs:446`

`Step.if_condition` was missing `#[serde(rename = "if")]`. The YAML key `if:` never populated the
field — `if_condition` was always `None`, so every step defaulted to `success()` and ran
unconditionally. `Job.if_condition` at line 295 had the annotation; `Step` did not. This silently
broke all step-level conditions (e.g. `if: ${{ 1 == 2 }}` ran instead of being skipped).

**Fix applied:** added `#[serde(default, rename = "if")]` to `Step.if_condition`.
Fixes `p1-expressions.yml` and `p0-step-execution.yml` E2E workflows.

### RCON-03 · Private registry authentication not implemented — **FIXED**
`crates/aksh-runner/src/worker/container_ops.rs`

Container steps pulling from private registries would 401/403 silently. Zero matches for
`docker login`, `password-stdin`, `registry_auth` in the codebase.

**Fix applied:**
- `RegistryCredentials { username, password }` struct added.
- `credentials: Option<RegistryCredentials>` field on `ContainerSpec` and `ServiceSpec`.
- Parsed from the `credentials.username` / `credentials.password` subfields of the container spec
  JSON (matching `ContainerRegistryCredentials` in `JobContainer.cs`).
- `docker_registry_login()`: writes credentials to a temp `--config` dir, calls
  `docker --config <tmpdir> login <registry> -u <user> --password-stdin`, retries up to 3× with
  5 s / 10 s exponential backoff (matching `ContainerOperationProvider.cs:470-499`). Drops the
  `TempDir` after pull to remove credentials from disk.
- `parse_registry_from_image()` matching `DockerUtil.ParseRegistryHostnameFromImageName`.
- `pull_image` now accepts `Option<&RegistryCredentials>` and routes through login when set.

## HIGH

### RHAND-01 · `github.action` context set to step name instead of step ID — **FIXED**
`crates/aksh-runner/src/worker/handlers/action.rs:28–31`

Official `StepsRunner.cs:118` assigns `github.action = actionStep.Action.Name` (the step ID).
`set_action_repository_context` was already correct, but `run_action` immediately overwrote
`github.action` with `ctx.step_name` (display name) in a duplicate call after the function.

**Fix applied:** removed the duplicate 4-line override. `set_action_repository_context` is the
single authority for `github.action`.
Unit test `set_action_repository_context_sets_action_to_step_id_not_display_name` added.

---

### RCON-01 · `docker exec` missing `-i` flag — **FIXED**
`crates/aksh-runner/src/worker/container_ops.rs`

`build_docker_exec_args` produced `exec -w <workdir> [--env K]... <id> <cmd>` with no `-i`.
Official `DockerCommandManager.cs` always passes `-i`. Without it, anything inside the container
that reads from stdin hangs or receives EOF unexpectedly.

**Fix applied:** inserted `"-i".into()` after `"exec".into()`. Test assertion updated.

---

### RCON-02 · Service container health-check backoff is hardcoded linear — **FIXED**
`crates/aksh-runner/src/worker/container_ops.rs` — `wait_for_services_healthy`

Official runner uses `GetExponentialBackoff(attempt, min=2s, max=32s, delta=2s)`.
aksh had a fixed array `[2, 3, 5, 5, 5, 10, 10, 10, 10, 10]` with a hard 10-attempt cap.

**Fix applied:** unbounded loop, delay = `min(2 + (2^attempt - 1) * 2, 32)` seconds.
No hard retry cap — the outer job-level timeout/cancel channel terminates a stuck wait.
Added explicit `unexpected health status` bail for non-standard status values.

## MEDIUM

### RCMD-01 · Regex recompiled on every log line — **FIXED**
`crates/aksh-runner/src/worker/matchers.rs`

`Regex::new()` was called inside the hot path once per matcher pattern per output line. On a job
with 10 k lines and 5 matchers × 2 patterns that is 100 k+ regex compilations.

**Fix applied:**
- `compiled_regexes: Vec<regex::Regex>` field added to `ProblemMatcher` (parallel to `patterns`).
- Compiled once in `add_from_file` after `validate_matcher_definition` (which already validates
  each regexp, so `expect()` is safe).
- Both the single-pattern and multi-pattern branches of `match_line` now use `&matcher.compiled_regexes[i]`
  directly, eliminating all `Regex::new()` calls from the hot path.

---

### RLIS-01 · Message dedup set not scoped to session lifetime — **FIXED**
`crates/aksh-runner/src/listener/broker_listener.rs`

`processed_message_ids: HashSet<i64>` lived for the process lifetime. On broker session
recreate (401/404/400/BrokerMigration), new server-assigned IDs could collide with old set
entries, silently dropping valid jobs.

**Fix applied:** `processed_message_ids.clear()` on every successful `create_session`,
scoping the set to each session's lifetime.
---

### RLIS-06 · RSA credential files written world-readable — **FIXED**
`crates/aksh-runner/src/settings.rs`

Official runner chmods `.credentials`, `.credentials_rsaparams`, `.runner` to 0600 on
Linux/macOS. aksh was writing at process umask (typically 0644), making the private RSA
key readable by group members on a shared host.

**Fix applied:** `restrict_permissions(path)` helper added; called after every `save_json`
in `RunnerConfig::save`. Uses `PermissionsExt::from_mode(0o600)` gated on `#[cfg(unix)]`.
---

### RLIS-02 · OAuth token refresh is reactive, not proactive — **FIXED**
`crates/aksh-runner/src/listener/oauth.rs` + `broker_listener.rs`

Token was fetched once at startup; re-fetched only on 401. `expires_in` was deserialized
but discarded, causing one failed request per token expiry cycle and a rare risk of
dropping a job dispatch in a tight expiry window.

**Fix applied:**
- `get_oauth_token` now returns `(String, Option<Instant>)` where the `Instant` is
  `now + expires_in - 300s` (5-minute early-refresh window).
- Broker loop checks `token_expires_at` at the top of every iteration and proactively
  calls `get_oauth_token` before the token expires.
- All three reactive re-acquisition sites updated to unpack the new return type.
